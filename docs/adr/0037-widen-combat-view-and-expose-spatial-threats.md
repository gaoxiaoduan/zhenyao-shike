# Widen Combat View and Expose Spatial Threats

## Context

青石岭切片把 `16:9` 战斗视野限制在地图横向约 `20%`，同时让法器从全场存活妖物中锁敌。结果是玩家难以观察妖潮、法器会击杀尚未入镜的妖物，扩大 PC 画布也不能改善空间判断。连续战场还需要一种不会被高密度单位淹没的导航表达。

## Decision

- 所有平台的 `16:9` 基准战斗视野统一显示地图横向 `35%`；世界视野最多随屏幕比例扩展至 `21:9`，更宽区域继续用于信息翼，不提供玩家任意缩放，也不按敌人数量动态缩放。
- 战斗视野与渲染密度独立：前者决定可观察的世界范围，后者只决定画面清晰度。
- 法器只能在当前战斗视野及约 `5%` 边缘缓冲构成的锁敌窗口中选取新目标；已发出的弹道和已经形成的范围效果可以在目标离开锁敌窗口后完成结算。
- 常驻战场雷达投影完整战场边界与主角绝对位置。普通妖物显示密度热区，灵蕴按相邻位置与价值聚合；精英妖物、妖王、战场事件和已发现地标使用精确标记。
- PC 雷达常驻于约 `220px` 的 HUD 或信息翼，移动端使用信息等价的紧凑版本。雷达由 Phaser 根据世界坐标绘制，不把逐帧单位坐标推入 Vue 响应式状态。
- 进入战斗视野的精英妖物始终显示场内生命条与受击反馈；普通妖物不显示生命条，妖王继续使用独立的高优先级生命表现。

本 ADR 部分取代 ADR-0017 的 `18%–22%` 基准视野、ADR-0036 的 `20%` 切片视野，以及 ADR-0002 中雷达不显示普通妖物的决定；它保留这些 ADR 的连续战场、跨平台公平、`21:9` 上限与危险预警原则。

## Consequences

- 扩大视野后必须重调生成环、妖潮密度、攻击预警和法器射程，不能只修改相机倍率。
- 雷达以聚合信息表达高密度单位，避免逐点绘制造成视觉噪声和移动端性能压力。
- 自动攻击的主要命中反馈发生在玩家可观察的区域内，屏外仍可完成已经承诺的弹道或范围伤害。
