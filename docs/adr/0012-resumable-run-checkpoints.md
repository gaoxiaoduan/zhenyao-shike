# Use Lightweight Resumable Run Checkpoints

## Context

移动浏览器可能因来电、锁屏、切换应用或内存压力而隐藏或回收标签页。一场完整历练约持续十一至十二分钟，因浏览器生命周期丢失整局进度会严重伤害移动端体验。

完整序列化所有敌人、投射物、特效、碰撞状态和计时器成本很高，也容易在版本更新后产生不兼容状态。

## Decision

页面进入后台时立即暂停整场历练。

系统在以下时机保存轻量历练断点：

- 完成一次升级选择后
- 完成一次战场事件结算后
- 历练进行中约每二十秒一次

断点保存随机种子、历练阶段、已用时间、玩家生命与经验、法器构筑、固定术法、已发生事件、本局收益和恢复所需的其他领域状态。断点不保存活跃敌人、投射物、视觉特效或 Phaser 运行时对象。

页面重载后，玩家可以从最近断点继续。系统根据断点重建当前阶段的敌群，清除旧投射物，并给予玩家两秒无敌保护。恢复成功后立即用新的状态覆盖旧断点，避免从同一升级选择或事件奖励处反复回档。

正常结算或玩家主动放弃历练时删除断点。

首领战采用单独的恢复边界：

- 页面仍存活而只是进入后台时，原地暂停并原地继续。
- 页面被回收或刷新时，从首领入场快照重新开始首领战。
- 入场快照恢复玩家入场时的生命、法器、术法和本局收益，首领恢复满血。
- 不序列化首领战中间的弹幕、召唤物、攻击时间轴或招式阶段。
- 首领战败或玩家主动放弃后立即删除断点。
- 断点恢复不消耗资源，也不施加额外惩罚。

## Consequences

- 移动端意外中断不会轻易损失整局进度。
- 恢复后的战场不会与中断前逐对象一致，但核心构筑、时间和收益保持一致。
- 断点格式需要版本号和迁移策略，并与长期养成存档分开。
- 恢复逻辑必须通过领域状态重建战场，不能反序列化 Phaser 对象。
- 刷新页面可以被用于重新挑战首领，但首发没有可信排行榜且本地存档本身可被修改，因此不为此引入复杂的服务端防作弊。
