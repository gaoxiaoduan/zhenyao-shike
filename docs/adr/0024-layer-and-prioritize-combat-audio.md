# Layer and Prioritize Combat Audio

## Context

高单位密度战斗需要依靠声音传达法器强度、首领预警和玩家危险状态，但若每次命中都独立播放音效，会形成噪音、削弱重要提示并增加性能压力。移动浏览器还限制未经过玩家手势触发的音频播放。

## Decision

- 每张地图使用一首分层战斗音乐，随单局时间阶段逐渐加入打击与旋律层；首领入场无缝切换专属段落。
- 每种基础和高阶法器拥有独立听觉轮廓，使飞剑、雷篆、阵旗、玄印等在混战中可辨认。
- 高频普通命中按短时间窗口聚合，不为每个碰撞实例单独播放声音。
- 音频系统设置并发上限和优先级：首领预警、玩家受伤、术法释放与法器进阶高于普通命中和小妖死亡。
- 首次有效玩家手势后才初始化和解锁音频上下文。
- 移动端震动只用于术法释放、法器进阶、首领破防和玩家重伤，不用于持续普通命中。
- 设置分别提供音乐、音效、震动和一键静音；不支持震动的浏览器静默忽略。

## Consequences

- 战斗事件需要输出语义化音频意图，不能在每个碰撞回调中直接播放文件。
- 音频管理器需要聚合、限流、优先级、并发声道和暂停恢复策略。
- 背景音乐分层必须与单局阶段和首领切换状态同步。
- 音频与震动失败不能影响战斗逻辑。
