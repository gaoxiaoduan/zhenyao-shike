# Use a Functional, Evolving Cave Hub

## Context

洞府需要承载局前准备、长期修行、解锁、剧情回看和再次出战。制作可自由行走的城镇会额外要求地图、寻路、碰撞、NPC 动画和跑腿交互，但不会增强核心妖群构筑循环。

## Decision

洞府实现为 Vue 功能型主界面，不作为 Phaser 可行走场景。

- 使用随境界成长的原创洞府插画作为背景。
- 首发保持五个主要入口：开始历练、修行突破、法器术法、镇妖录和设置。
- 可研习内容、刻印札记和存档异常使用克制的角标提示，不设置 NPC 跑腿任务。
- 常驻 NPC 控制在二至三名，只通过立绘和短对话参与剧情，不在洞府实时移动。
- 炼气阶段洞府简陋；筑基后增加阵台与藏经架；结丹后十刻镇妖盘逐步完整并发光。
- 从启动或结算回到再次历练，正常路径不超过三次点击。

## Consequences

- 洞府视觉需要按大境界提供至少三种状态，并能叠加刻印变化。
- 所有核心功能必须可直接触达，不能为了氛围隐藏成难以发现的场景热点。
- NPC 演出可以复用 Vue 对话组件和立绘资产，不需要战斗精灵动画规格。
- 若未来增加可行走社交区域，应作为独立产品扩展，而不是让洞府主界面逐步膨胀。
