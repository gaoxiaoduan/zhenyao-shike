# 青石岭重玩基线证据

日期：2026-08-18
范围：桌面 Chromium、1280 × 720、青石岭固定种子验收场景。

## 结论

0:30 的正常速度截图和固定种子检查点截图已经确认：此前的“大块黑色遮挡”是真实的 WebGL 纹理问题，不是截图或 DOM 面板问题。根因是普通妖物图集为 `10240 × 256`，超过 WebGL 常见的 `8192px` 最大纹理宽度。修复后拆为两个 `5120 × 256` 图集，在 2:00 高密度检查点的黑色像素占比从 `8.08%` 降至低于 `1%`，且妖物轮廓恢复可见。

## 试玩观察与边界

正常速度脚本曾观察到：首次升级为青锋剑匣 `Lv.1 → Lv.2`；妖巢暴动说明出现；在尚未形成高阶法器时，普通妖物贴身导致约 2:49 / 3:17 失败。这个结果足以说明失败反馈链路可达，但不足以替代真人判断成长节奏，也不把自动化失败当成最终胜率结论。

妖王演练已有浏览器回归覆盖，并额外断言进入后不存在“战场事件说明”弹窗；因此演练不会被成长阶段事件说明打断。完整妖王招式、破绽窗口、胜利/失败归因仍需真人试玩确认。

| 自动化已经证明 | 仍需要真人试玩 |
| --- | --- |
| 固定种子阶段时刻、WebGL 图集不再产生黑块、雷达/HUD/妖王血条存在 | 正常速度下首次升级与首件高阶法器是否按预期出现 |
| 8:30 高密度场景仍能看到普通妖物、精英、灵蕴和威胁边界 | 三种代表构筑是否都能完成事件并进入妖王战 |
| 妖王演练直接进入妖王，不弹成长事件说明 | 妖王战是否主要落在 90–120 秒、失败是否能归因于可识别招式 |
| 失败结算、个人记录与“再来一把目标”链路可达 | 五名首次玩家无讲解试玩，以及移动端/减少动态效果复核 |
