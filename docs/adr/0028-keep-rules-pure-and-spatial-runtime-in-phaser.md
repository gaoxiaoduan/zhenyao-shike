# Keep Rules Pure and Spatial Runtime in Phaser

## Context

规则需要在 Vitest 中快速、确定地验证，但把整个战斗实现成独立于 Phaser 的自研物理或 ECS 会重复实现坐标、碰撞、对象生命周期和渲染集成。另一方面，把升级、伤害、境界和事件规则散落在 Phaser 场景回调中，又会使规则难以复现和测试。

## Decision

采用“纯 TypeScript 规则模块 + Phaser 空间运行时”的分工。

Phaser 负责：

- 世界坐标、移动和碰撞检测
- 镜头、对象池、生成位置和场景生命周期
- 精灵、动画、粒子、音频触发和渲染

纯 TypeScript 规则模块负责：

- 法器属性、伤害和控制效果计算
- 升级候选、保底、吐纳、周天运转和法器进阶
- 单局阶段、事件时序和首领阶段状态机
- 本局收益、境界推进和内容解锁

Phaser 将攻击命中、拾取、进入区域等空间事实转换为领域输入，规则模块返回伤害、控制、死亡、奖励和阶段变化等结果。历练状态机只接收由会话传入的逻辑时间增量；完整暂停时不推进，也不直接读取系统时钟。

内容配置使用稳定内容 ID，不保存或引用 Phaser 对象。Vue 仍只通过 `GameSession` seam 提交粗粒度命令并接收领域事件。

## Consequences

- 高价值规则可以在不创建画布和场景的情况下快速测试。
- 实际碰撞边界、生成安全区和对象池仍需 Phaser 集成测试。
- Phaser 适配器必须把空间事件翻译成明确领域输入，不能让规则模块反向调用场景。
- 固定随机种子可以复现内容与规则选择，但除非记录完整输入，不保证整场空间战斗逐帧重放。
