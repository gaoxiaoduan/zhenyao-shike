# Use a Layered Game Testing Strategy

## Context

镇妖十刻同时包含纯规则、Vue 产品界面、Phaser 实时运行时、浏览器生命周期、PWA 缓存和 Cloudflare 端点。只用模拟 DOM 的单元测试无法验证旋转、离线、分享和 WebKit 行为；只依赖端到端测试又会使规则测试缓慢且难以定位失败。

## Decision

采用分层测试策略：

- Vitest 测试纯 TypeScript 领域规则，包括随机种子、升级候选保底、法器槽位、进阶配方、数值计算、境界推进、断点和存档迁移。
- 核心规则不读取系统时间、全局随机数或 Phaser `Scene`；随机数和时钟通过窄接口注入，使固定种子的规则场景可复现。
- Vue 组件使用 Vitest 与 Vue Test Utils，从玩家可见输出、操作和事件测试升级选择、暂停、结算和存档导入，不访问组件内部状态。
- 不使用大面积快照作为行为正确性的主要证据；稳定的小型视觉结构可以把快照作为辅助断言。
- 使用 Playwright 覆盖 Chromium、WebKit 和桌面 Firefox 的关键流程，包括首次教学、方向变化暂停、页面重载续战、离线启动、版本更新和分享降级。
- 建立独立的固定种子压力场景，测量接近对象预算时的帧率、对象数量和内存增长，不把设备性能断言混入普通单元测试。
- CI 将领域规则、组件行为和一组关键浏览器流程作为合并门槛；完整设备性能验证在发布流程中运行。

## Consequences

- 测试目录和配置需要明确区分 Node/DOM、浏览器端到端与性能场景。
- Phaser 适配层仍需少量集成测试，但规则覆盖不应依赖启动完整画布。
- 固定种子只保证可控内容与规则复现，不自动保证跨浏览器逐帧像素一致。
- Playwright 浏览器和 PWA 测试会增加 CI 时间，需要保留快速的提交级测试集合。
