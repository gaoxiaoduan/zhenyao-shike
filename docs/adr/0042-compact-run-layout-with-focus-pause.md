# 小窗历练使用紧凑布局并在窗口失焦时暂停

## Context

青石岭需要支持浏览器小窗口中的“小窗历练”，让玩家在有限桌面空间里继续完成移动、自动攻击、拾取、升级和暂停。它不是系统级或浏览器原生画中画，也不能因为窗口变小就牺牲战场可读性或让角色在玩家切换窗口时继续承受伤害。

## Decision

- 首页提供明确的“小窗历练”入口；桌面历练中可以在标准布局与紧凑布局之间切换。两种布局共享同一个 `GameSession`、Phaser 规则和 `InputIntent`，不复制一套战斗运行时。
- 紧凑布局保持 `16:9` 基准战场、核心生命/经验、妖王状态、事件提示、触控施法、升级选择和手动暂停；收起两侧构筑与阶段信息翼，把空间让给战场。
- 紧凑布局不受标准桌面 `960 × 540` 最小窗口门槛限制，但仍遵守横屏、`safe-area`、固定视野和现有渲染密度规则。它不提供任意缩放、后台挂机或自动战斗。
- 紧凑布局窗口触发 `blur` 时立即清空移动意图并完整暂停。窗口重新获得焦点后进入“窗口已恢复”确认态，由玩家点击“继续历练”才恢复；多个暂停原因仍由会话统一叠加与解除。
- 标准布局继续使用既有页面可见性暂停语义；本决策不把普通窗口失焦扩展成全站强制暂停，避免改变已稳定的桌面历练行为。
- 战场事件说明、升级、妖王战和结算在紧凑布局中继续使用同一套 Vue 覆盖层；原生 Document PiP 另行研究，不作为本能力的实现路径。

## Consequences

- 小窗历练可以复用当前战斗规则和存档/结算链路，布局切换不会改变本局记录或“再来一把目标”。
- 会话暂停原因需要区分窗口失焦与页面隐藏、方向变化、尺寸不足、手动暂停和决策暂停；继续按钮不能只释放其中一个原因。
- 失焦后必须由玩家确认恢复，浏览器事件顺序和不同桌面浏览器的焦点行为需要端到端验收。
- 后续如果引入原生 Document PiP，必须先通过独立 POC 验证跨窗口输入、渲染、音频和关闭生命周期，不能直接把本布局 reparent 到 PiP 窗口。
