# Collect First-Party Anonymous Gameplay Analytics

## Context

页面访问和加载性能无法回答法器选择率、死亡阶段、首领胜率、断点恢复率和真实设备帧率等平衡问题。完全没有玩法数据会使首发验证依赖零散反馈，但账号、玩家画像和跨站追踪又不符合本地优先、低摩擦的产品方向。

## Decision

部署一个最小 Cloudflare Worker 统计端点，将匿名聚合玩法事件写入 Workers Analytics Engine。Cloudflare Web Analytics 用于页面访问与真实用户性能，玩法统计端点只补充游戏领域指标。

客户端在一局结束时批量提交：

- 游戏版本、地图、境界和局前术法
- 最终法器构筑
- 胜负、历练时长和死亡来源类别
- 平均帧率档位与画质档位
- 是否使用断点恢复
- 是否点击分享

不得提交姓名、账号、存档内容、精确位置、设备指纹或跨设备身份。应用不生成用于追踪玩家的永久统计 ID，也不把请求 IP 写入玩法数据集。

设置中提供关闭匿名玩法统计的选项。统计请求失败、被拦截或被关闭时，不得影响战斗、结算、存档或分享。

该 Worker 不保存或修改任何游戏业务状态，不构成账号或云存档后端。

## Consequences

- 可以按版本和内容聚合分析平衡与性能，而不能追踪单个玩家的长期行为路径。
- “次日留存”等跨会话指标只能使用 Cloudflare Web Analytics 的聚合能力或后续另行设计，玩法事件本身不提供玩家级归因。
- 客户端事件结构需要版本化，服务端必须限制方法、载荷大小、字段枚举和请求速率。
- 隐私说明需要清楚列出统计字段和关闭方式。
- 统计端点与核心游戏必须保持故障隔离。
