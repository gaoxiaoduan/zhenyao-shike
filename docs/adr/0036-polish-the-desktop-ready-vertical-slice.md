# Polish the Desktop-Ready Vertical Slice Before Content Expansion

## Context

在 ADR-0035 的青石岭核心玩法切片可运行后，PC 窗口仍固定显示 `16:9` 战场，宽屏空间没有被利用；战斗没有声音；首页、HUD、选择和结算仍以功能占位为主。本阶段的目标是把同一个切片打磨成可展示的完整体验，而不是提前扩建完整洞府和长期系统。

## Decision

- 本轮只精修临时洞府首页、青石岭战场、战斗 HUD、暂停与选择界面、设置和结算；不扩展修行突破、图鉴、NPC、完整洞府或 PWA。
- 桌面以 `1280 × 720` 为设计基准，低于 `960 × 540` 时暂停并提示扩大窗口；桌面窄窗不再被当成移动设备旋转。PC 默认窗口化，提供显式全屏；移动端仍可在开始历练的有效手势中进入全屏。
- 战场遵守 ADR-0017：`16:9` 基准视野保持地图横向约 `20%`，随窗口最多扩展到 `21:9`，更宽空间只显示信息翼；不提供任意缩放。渲染密度桌面最多 `2×`、移动端最多 `1.5×`。
- PC 保留 `WASD`、方向键、`Space`、`E`、`Esc` 默认键位，并为移动、术法和暂停提供冲突检测、恢复默认与本地持久化的重绑定。
- 使用一套原创、可替换的青石岭像素场景、角色、妖物与法器图标，通过稳定资源 ID 引用；Vue 继续管理产品 UI，Phaser 继续管理战场表现。
- 当前切片使用程序合成的原创声景：洞府、开局、`2:30`、`5:30`、`8:00`、妖王、胜利和失败段落；基础与高阶法器具有可区分音色。普通命中聚合，重要提示保留声道，选择界面压低音乐，完整暂停静音。默认音乐 `60%`、音效 `80%`，提供分项音量、静音和关键移动端震动设置。
- 结算显示存活时间、击杀数、事件状态、法器构筑、保留资源、首次胜利妖丹、新纪录、死亡来源和一句规则化提示，并保留快速重试与返回洞府。
- 设置提供清晰度、大号文字、减少动态和桌面键位；本阶段不实现移动摇杆镜像、尺寸和透明度调节，这些仍由 ADR-0025 约束首发版本。
- 使用 Vitest 覆盖领域/设置/音频与 Vue 公共行为，并用 Playwright 验收 Chromium、Firefox 和 WebKit 的 `1280 × 720`、超宽、最小窗口与持久化流程。

## Deferred constraints

- ADR-0029 的完整语言键迁移不在本轮展示切片内。本轮新增文案仍只交付简体中文；此处不撤销 ADR-0029，增加第二语言前必须先把展示文案迁移为稳定语言键。
- ADR-0019 的完整长期事件历史、新纪录分类和其他主线节点数据，待相应长期存档模型落地后扩展；本轮只记录青石岭可解释数据。

## Consequences

- 超宽 PC 获得更多战场横向空间和独立信息翼，但不会突破公平视野上限。
- 音频、设置和结算通过窄会话事件与 Phaser 隔离，资源失败不能影响战斗规则。
- 生成素材是本切片的原创演示资产，不视为最终首发美术锁定。
